# Q04: авторизация панели и границы API

Дата: 3 октября 2026. Статус: **IN_PROGRESS — заключительная проверка исправлений**.

## Область

Проверены `web/auth.rs`, middleware `web/mod.rs` и авторизация обработчиков
`web/api`. Инвентаризация охватывает 56 методов: POST `/api/login` публичный,
55 остальных принимают `AuthGuard`. HTML требует cookie; Basic предназначен
для API. TOTP для входа в web-панель отсутствует и не получает фиктивный PASS;
VPN TOTP относится к отдельному разделу аудита.

Положительные мутации бизнес-данных, транзакции INI, restore и control остаются
Q05/Q07. Здесь проверены запреты выполнения этих методов без прав и при
недопустимом Origin, отсутствие изменения конфигурации, identity, сессии и PID.

## Проверки

Исходный квалифицированный release `f5c4bd0a36ba23dd2ba27ec638b5960b19414281f10fec59122f2f009eced199`:
289 checks PASS и отдельные наблюдения с воспроизведением F001–F003.
Проверены три способа неавторизованного доступа к каждому из 55 методов,
HTML cookie-only, nonce CSP, заголовки/cache, CSRF каждого mutator, Origin/Referer,
CLI без Origin, TTL и независимо подписанные invalid/expired токены,
trusted/untrusted proxy chain, HTTPS и prefix, allowlist страниц/assets/API,
lockout/expiry, сохранение и отзыв cookie через restart, ошибки и повреждение
session.gen/session.key, explicit passwordless mode, настоящий native TLS и HSTS.

Настройки CSRF сопоставляют host/port; scheme полного URL в allowed_origins
нормализуется согласно существующему документированному контракту. Это не
проверка строгого равенства всего origin. Конфигурационные файлы остаются INI;
JSON используется для API и аудиторских свидетельств.

Новые детерминированные Rust-регрессии проверяют очередной admission после
блокировки, учёт отменённого running job до возврата permit, успешную/отключённую
политику и Basic grammar. 116 JS-групп Q03 повторно прошли.

Стенд .11 использует отдельные NET/mount/PID namespaces и точный SHA release.
Полные host snapshots, идентичность действующего сервиса и его бинарник сравниваются
до/после. Обычный сервис не заменяется. Для повторения служат
`scripts/audit_web_auth_lab.py` и `scripts/audit_web_auth_boundary.py`.

Диагностические неуспешные попытки сохранены: ожидание готовности worker до
identity generation, lazy session-key initialization, canonical redirect expectation
и ошибочная CP1251-конверсия первого локального патча. Последняя исправлена до
окончательной квалификации; первый ошибочный unit input не используется как PASS.
Предыдущий reuse Rust-тестов в Q03 не обнаруживал зависимость assertions от HTML;
текущий полный прогон устраняет этот пробел.
