## Q03-F001 — Незагруженная политика выглядела доступной для сохранения

При задержке или ошибке GET `/api/blocked/settings` поля оставались доступны,
а Save отправлял значения по умолчанию. Backend отклонял первоначальную запись
без `expected_revision`; фактическая перезапись конфигурации не воспроизведена.
UI скрывал границу между загруженными настройками и начальной заготовкой.

Исправлено: поля и Save блокируются до успешной загрузки настроек и ревизии,
параллельные загрузки/сохранения не допускаются. Ошибка остаётся видимой;
Reload повторяет запрос. Fieldset также блокирует клавиатурное редактирование.
На мобильном экране политики расположены последовательно.

## Q03-F002 — Отказ canonical defaults включал дублирующую JS-схему

Сбой GET `/api/config/defaults` не мешал Add profile: панель создавала профиль
из большого встроенного объекта. Эта копия могла расходиться с Rust defaults.
При повторной неудачной загрузке мог сохраняться ранее полученный шаблон.

Исправлено: JS-копия удалена; загрузка использует общий `apiFetch` и сбрасывает
старый шаблон. При отказе показано локализованное сообщение, Add заблокирован.
Просмотр и редактирование успешно загруженного конфига продолжают работать;
Reload восстанавливает добавление только после получения canonical template.
