## Q03-F001 — Незагруженная политика выглядела доступной для сохранения

При задержке или ошибке GET `/api/blocked/settings` поля оставались доступны,
а Save отправлял значения по умолчанию. Backend отклонял первоначальную запись
без `expected_revision`; фактическая перезапись конфигурации не воспроизведена.
UI скрывал границу между загруженными настройками и начальной заготовкой.

Исправлено: поля и Save блокируются до успешной загрузки настроек и ревизии,
параллельные загрузки/сохранения не допускаются. Ошибка остаётся видимой;
Reload повторяет запрос. Fieldset также блокирует клавиатурное редактирование.
На мобильном экране политики расположены последовательно.

## Q03-F002 — Отказ canonical defaults включал дублирующую JS-схему

Сбой GET `/api/config/defaults` не мешал Add profile: панель создавала профиль
из большого встроенного объекта. Эта копия могла расходиться с Rust defaults.
При повторной неудачной загрузке мог сохраняться ранее полученный шаблон.

Исправлено: JS-копия удалена; загрузка использует общий `apiFetch` и сбрасывает
старый шаблон. При отказе показано локализованное сообщение, Add заблокирован.
Просмотр и редактирование успешно загруженного конфига продолжают работать;
Reload восстанавливает добавление только после получения canonical template.

## Q03-F003 — Поздний ответ перезаписывал новое состояние

На страницах логов, транспорта и блокировок ручное обновление могло пересекаться
с таймером или другим запросом. Старый ответ заменял новые данные; его завершение
снимало индикатор ещё выполняющейся загрузки. Новая регрессия до исправления
подтвердила третий фоновый запрос поверх двух незавершённых.

Исправлено: последовательность запросов определяет владельца данных и индикатора.
Фоновый запрос пропускается, пока есть незавершённый; ручное обновление после
изменения лимита логов или снятия блокировки сохраняет приоритет. После destroy
поздний ответ не меняет журнал/состояние транспорта. Таймеры очищаются.
Это не отмена уже отправленного HTTP-запроса и не гарантия сетевого timeout.

## Q03-F004 — Ошибки выдавались за пустой журнал или исчезали под фильтром

GET журнала блокировок с `{ok:false}` очищал обе таблицы и показывал «Нет
заблокированных IP». Ошибка логов попадала в массив строк без уровня и исчезала
при выбранном ERROR либо поисковом фильтре. Сбой не означал отсутствие записей.

Исправлено: отдельное сообщение role=alert, сохранение последнего успешного
снимка, empty-state только после успешной загрузки без текущей ошибки. Ошибка
логов не становится строкой журнала. Countdown блокировок не удаляет записи:
удаление подтверждает следующий успешный GET. При ошибке countdown заморожен;
показанные данные являются последним полученным снимком, а время — оценкой.
